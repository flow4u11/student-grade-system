# ส่วนที่แก้เองได้ใน VSCode

แก้บนเครื่องและตรวจผลก่อนเผยแพร่ ใช้ข้อมูลสมมติสำหรับทดสอบ ฐานข้อมูลจริงไม่ควรถูกใช้เป็นชุดทดลอง

## วิธีที่ง่ายที่สุด: ปรับผ่านเว็บ

- เปลี่ยนชื่อโรงเรียน โลโก้ สีเริ่มต้น และข้อมูลติดต่อ: บัญชีผู้ดูแล → ตั้งค่า → ข้อมูลโรงเรียน
- เปลี่ยนชื่อเล่น รูปภาพ อีเมลติดต่อ และประวัติ: กดโปรไฟล์ด้านล่าง Sidebar
- ชื่อจริงครูภาษาไทย/อังกฤษ: ผู้ดูแล → บัญชีครู → แก้ไข
- ข้อมูลนักเรียน เลขที่ และรหัส: โปรไฟล์นักเรียน → แก้ไขข้อมูลนักเรียน
- กำหนด PIN นักเรียน: โปรไฟล์นักเรียน → ตั้ง/เปลี่ยน PIN ใช้เฉพาะนักเรียนที่มีสิทธิ์ดูแล แจ้ง PIN เป็นส่วนตัว
- Theme ส่วนตัว: ตั้งค่า → Theme ส่วนตัว เลือกชุดสี ปรับสีเอง และเลือก Classic/Glassmorphism/Neobrutalism มีผลเฉพาะเบราว์เซอร์นั้น

## รหัสผ่านผู้ดูแล

รหัสผ่านไม่ได้อยู่ในโค้ด และไม่ควรเขียนลง GitHub หรือไฟล์ที่ส่งต่อ ข้อมูลบัญชีจริงอยู่ใน Supabase Authentication เปลี่ยนรหัสผ่านผ่านการจัดการบัญชีของ Supabase หรือเครื่องมือผู้ดูแลที่ใช้ Auth Admin API ด้วยค่าลับฝั่งเซิร์ฟเวอร์ แล้วลงชื่อเข้าใหม่

`scripts/create-admin.mjs` ใช้สร้างบัญชีผู้ดูแลใหม่ ไม่ใช่เปลี่ยนรหัสผ่านบัญชีเดิม และต้องตรวจ URL ฐานข้อมูลก่อนยืนยันเสมอ ไฟล์ `.local` ที่สร้างไว้สำหรับข้อมูลเข้าสู่ระบบเป็นไฟล์ส่วนตัว ห้ามเผยแพร่

อีเมลติดต่อในโปรไฟล์เป็นข้อมูลติดต่อ การเปลี่ยนช่องนี้ไม่เปลี่ยนบัญชี Login หรือรหัสผ่าน

## ส่วนที่ควรให้ผู้พัฒนาช่วย

อย่าแก้ `supabase/migrations/`, API ใน `src/app/api/`, `src/lib/permissions.ts`, การคำนวณใน `src/lib/grading.ts`, PIN/Session หรือกฎเผยแพร่เกรดโดยไม่ตรวจความปลอดภัย สิ่งเหล่านี้ส่งผลต่อสิทธิ์และข้อมูลจริง การเปลี่ยนสีด้วย CSS ไม่เปลี่ยนกฎเกรดหรือการคำนวณ GPA

หลังปรับโค้ด ใช้ `npm run typecheck` และ `npm run lint` สำหรับการเปลี่ยนข้อความ/CSS จากนั้นตรวจหน้าที่เปลี่ยนก่อนเผยแพร่ การแก้โค้ดในเครื่องไม่เปลี่ยนเว็บออนไลน์จนกว่าจะ Deploy

## GitHub สาธารณะ

ประวัติ Git ใน checkout ส่วนตัวมีข้อมูลผู้เขียนและบันทึกภายใน จึงปิดการ Push จาก checkout นี้ไว้ ใช้ clone จาก `main` ของ GitHub สาธารณะสำหรับแก้และ Push หรือส่งออกไฟล์ที่ตรวจแล้วโดยไม่รวมประวัติส่วนตัว อ่าน [ขั้นตอนเผยแพร่](PUBLIC_RELEASE.md)
